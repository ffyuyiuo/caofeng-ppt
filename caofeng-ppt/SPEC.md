# caofeng-PPT 技能规格（SPEC v1）

交付对象：曹风。用途：把一份 Word 文档做成**电影级、可编辑、带动态背景**的 PPT。
本文件是**契约**。每条硬指标都必须在 §7 找到对应机器闸；闸不通过就不出片。
参数一律注明来源：`[Deck]`= 来自 171 个模板的 OOXML/文本实测，`[Prompt]`= 来自 52 个提示词块统计，`[Video]`= 来自教程视频转写。取不到的写「未取到」，禁止编造。

---

## 0. 范围

做：Word(.docx) → 分镜 → 联网取素材 → 写提示词包 → 投放文生图/图生视频 → 装配 .pptx → 机器验收。
不做：① 不代充任何模型账号；② 不生成冒牌「已成功」提示；③ 不承诺本机没有的能力（本机无视频生成模型，视频一律走豆包/即梦网页版）。

## 1. 输入与输出契约

| 项 | 契约 | 校验 |
|---|---|---|
| 输入 | 1 个 .docx（可附 1 段风格方向文字） | 读不到正文则终止并说明 |
| 中间产物 | `work/<作业名>/`：shots.json / materials/ / promptpack/ / gen/ | 目录存在且非空 |
| 最终产物 | 1 个**可编辑** .pptx + 1 份验收报告 md | python-pptx 能打开；文本是真文本框 |
| 页幅 | 16:9，12192000×6858000 EMU | G8 |
| 时长 | 封面/隔页动态背景视频 5–10s `[Prompt 16/22 写明时长]` | G6 |

## 2. 七阶段流水线（每阶段的产出与判据）

**S1 解析 Word** — 输出 `outline.json`：`{title, chapters:[{name, pages:[{role, headline, body[], data[], mood, entities[]}]}]}`。
- `entities` = 文档里的专名/产品/地点/人物，是 S3 搜索词的唯一来源（不得凭空发明主题）。
- 每页必须有 `role ∈ {cover, divider, statement, data, process, compare, quote, closing, appendix}`。
- **目录条目（Word 样式 `toc 1/2/3`）不进分镜**：它们带制表符页码，当正文排就会出现
  「第2章 为什么是现在\t4」这种标题页（车联体实测 21 条）。剥离记在 `outline['dropped']`（含原文与理由），
  G13 据此豁免这些句子并把条数写进报告——**没有这本账，agent 的唯一出路就是缩源**（v17 造假源的动因）。
- 分页同时受句数与字数约束：`--per-page` 是句数上限，`page_chars_max` 是字数上限，先到先切。
  只数句子时一句 200 字的长句照样把整页顶成文字墙（实测 26 页命中 G19、17 页装配丢正文、9 页文字挤出留白区）。
- 判据：章节数>0；每页 headline ≤ 16 字且含数字或判断词（Action Title）。

**S2 分镜** — 输出 `shots.json`：每页一条 `{page, role, shot_intent, motion, need_material, asset_kind, tech_recipe}`。
- `asset_kind ∈ {video_bg, image, gif, field, none, table}`。`gif` 是语料里独立的一类手法
  （133 个模板含 161 个 GIF，最少 24 帧、中位 51 帧），不是视频页的替补。
- `shot_intent` 用「镜头语言」写，不用「排版语言」写。词表来自 171 模板实测：
  morph 平滑推镜 `[Deck morph 192 次]` / 整页视频背景 `[Deck mediacall 2128 次]` / 动图元素划过 `[GIF 162 个]` / 文字入场 `[entr:22 242 次、entr:10 209 次]` / 粒子光带扫描 / 城市生长 / 破浪 / 卷轴展开 / 撕纸 / 水墨晕染 / 胶片轮播 / 3D 微缩等距 / 热气球-火箭-列车-飞机 位移。
- `tech_recipe` 必须指到 kb 里的技法卡 ID（`kb/deck_tech.json`），否则该页判为「无方案」。
- 判据：全场至少 1 个 cover 视频背景、**成品里**≥30% 页面真的带动效、隔页必带 morph 或视差
  （build 会给每个隔页自动补平滑，文字淡入不算视差）。


**S3 联网取素材** — 输出 `materials/` + `materials/manifest.jsonl`（每条含 url、license、宽高、文件大小、SHA1、所属 page）。
- 只收**高清无水印**：短边 ≥1920；不得含图库水印；许可可举证。
- 国内站点直连；国外站点走代理 7897。
- 用途双轨：① 直接当页面图；② 当 AI 生成的**参考图**（图生图/图生视频的首帧素材）。
- 判据：G3 逐条核；缺素材的页降级为矢量色场而不是放占位假图。

**S4 写提示词包** — 输出 `promptpack/<page>.{image,first,last,video,gif,negative}.txt` + `promptpack/pack.json`。
- 严格按 §3 的槽位语法；每条 prompt 必须点名它使用 `materials/` 里哪张图作为附件。
- `pack.json` 只是缓存：`check` 会重新读每个 `.txt` 打分，改了提示词不重跑 pack 会被判不合格。
- **提示词种类必须与 `asset_kind` 一致**：`scaffold` 会清掉不匹配的历史提示词
  （`image` 页不留 `video` 段、`gif` 页留 `image+negative+gif`、`field/none/table` 页一份不留）。
  实测坑：把页 1 从 `video_bg` 改成 `image` 后，旧 `p001_video.txt` 还在，投放卡就叫人去跑一段
  根本不会嵌进成片的视频；`field` 页留着提示词则会让 G11 误判"写了提示词却没产物"。

- 判据：G2 槽位齐全 + G5 留白占位声明存在。

**S5 投放模型** — 出图/出视频/出动图**一律走网页版免费额度**（即梦/豆包），产出统一落到 `gen/<page>/`。
- **禁止使用 Qoder 自带 ImageGen**：它消耗用户的模型积分（2026-11-05 用户明令），而且右下角会烧「AI生成」水印。
  技能里任何"自动出图"的说法都不成立；真正全自动的只有两条——S3 联网抓 CC 授权真实照片、
  以及装配时的矢量色场 / `scripts/make_gif.py` 确定性生成（零模型调用）。
- 人工通道：即梦/豆包网页版，由 `delivery_card.md` 给出点击级步骤 + 可直接粘贴的文本块 +
  **要上传的参考图（"要上传的附件"小节逐条给绝对路径：优先爬到的真实素材，其次本页已生成的文生图/首尾帧）**
  + 回收文件名。需求 4 说的"附带上传的图片用于图生视频/动图"就落在这小节，只写"本页文生图结果"不算交代。

- 静帧背景/插图：即梦「图片生成」16:9 + 高清/2K 档（短边必须 ≥1080，否则装配会降级成色场）。
  用户知情坚持用低清时 `pickup --force` 可收，但必须留痕：写 `gen/pNNN/lowres_force.json`，
  check 报告加「低清强制收下声明」、结论行写明"不算高清交付"——不许静默混过验收。
- 动图页走即梦的「图片动画/循环动图」，存成 `gen/<page>/gif.gif`（或同目录任意 `*.gif`）；不想手动就用 `make_gif.py`。
- 判据：G11 每张 gen 产物都能回指一条 prompt；未回收的页在报告里标「待补」，不许谎报完成。
- **等待与续接（契约条款，不是礼仪）**：投放卡必须一次给全（按模型分组 + 提示词全文代码块 + 绝对路径 +
  回收文件名），并只问一次固定问题「视觉资源是否已下载就绪？就绪请回复 **是**」；素材未回传期间
  不许输出终止性措辞、不许把 goal 标完成、不许重新分镜。这条由机器兜底：G11 把"有提示词无产物"判硬伤，
  `check` 退出码非 0 时本来就无法宣布交付。续接不需要状态文件——`--work DIR` 目录本身就是断点。


**S6 装配** — 输出 .pptx。写法见 §6.3（视频整页背景 + morph + 蒙版 + 文字层入占位区 + 文字入场 timing 树）。
- 动图叠在蒙版**之上**（蒙版会把水墨/闪光这类元素动效压没）。
- 每个文本框都写 `p:timing` 的 `entr` 入场节点（语料高频 `presetID=10` 淡入，逐条 120ms 递进），
  让"≥30% 页面有运动"这件事在成品 XML 里数得出来，而不是只在分镜计划里写着。
- 判据：G7 可编辑（文本框数>0、无整页截图代替文字）；G4 文字压图对比度达标。

**S7 验收** — `caofeng.py check --work DIR --render` 跑 G1–G29 全部闸 + `caofeng.py shots` 逐页导出
PNG 并拼成带页码标签的图供人眼复核；输出 `report/验收报告.md`。
闸本身要自证咬得住：`python scripts/test_gates.py`（60 项以上反向自证，2026-11-19 实测 167；
`check_docs.py` 把下限与代码条数对账；反例必须被拦、正例必须放行；
退出码 1=有闸不咬或成品不合格，3=自检脚本自己崩了，结果不可信）。
- 判据：G1–G29 全绿，且我亲眼看过渲染图（不能只看统计）。
- 命令序列只在 SKILL.md 的"七阶段流水线"bash 块里定义一次，本节只写各阶段产出与判据；
  两处各写一遍必然漂（2026-11-09 干净上下文复验就是这么抓到 refine/ack 在 SPEC 有、bash 块没有）。


## 3. 提示词语法（从 52 个真实块统计）

### 3.1 图片提示词 = 带标签九段式
语料里 NO.165/172/173/174 等直接以小标题写：`主体特征 / 构图方式 / 镜头角度 / 光线方向(光线效果) / 色彩搭配 / 材质细节 / 画面风格 / 背景元素 / 画面参数`。
强制规则（括号为实测覆盖率）：
1. 开篇声明画幅与用途：「生成一张 16:9 横版…PPT 背景图」 `[画幅 13/20]`
2. **位置用百分比和区域写**，不用「左边一点」：「占画面宽度约 18%、高度约 30%」「左上卡片位于画面左侧约 5%～35% 区域」 `[位置百分比 5/20，仅高阶模板使用 → 本技能强制]`
3. 色彩**闭集**：「整体色彩严格控制在深蓝、科技蓝、冰蓝、青蓝范围内…避免其他颜色」 `[色彩管控 11/20]`
4. 光线四件套：主光源 + 轮廓光 + 反射光 + 体积光 `[光线 12/20]`
5. 空间三段：前景/中景/远景 + 空气透视 `[层级纵深 12/20]`
6. **留白占位**：「卡片内部保持干净、完整、留白，不放任何文字」「上半部分保持大面积暗色留白，便于后期添加 PPT 标题」 `[留白占位 仅 4/52 → 本技能对图片/视频强制，这是可编辑的前提]`
7. 结尾画质锚点：8K/HDR/电影级渲染/Octane/UE5 `[分辨率画质 9/20，渲染质感 12/20]`
8. 平均长度 **809 字**（图片）`[Prompt]`；短于 350 字判为描述不足（G2）。

### 3.2 视频提示词 = 六段式
1. **参考帧声明**：「附件1 作为首帧」「以参考图作为唯一构图依据」「附件图片是最后完成的效果，作为视频尾帧」 `[首尾帧参考 16/22]`
2. **全局参数**：N 秒 + 16:9 + 超高清 + 风格基调 `[时长 16/22]`
3. **秒级分镜**：`【0–1 秒：阶段名】…`，每段只讲一个动作；用「镜头缓慢推进/拉远/下降」写运镜 `[秒级分镜 6/22；镜头运动 17/22]`
4. **因果顺序显式化**：「扫描顺序必须严格为 左→中→右，不得同时」「点击之前不能生长，必须点击之后才开始生长」 `[动作逻辑 5/22 → 强制]`
5. **运动与镜头约束**：「镜头保持稳定平滑运动」「固定机位，不推拉不旋转不变焦」「不要剧烈抖动、不要跳切」 `[运动约束 17/22]`
6. **定格收束**：「最后 0.5 秒画面逐渐稳定，精准匹配结尾参考图片的构图和元素位置」 `[定格收束 6/22 → 有尾帧的页强制]`
- 平均长度 **1011 字** `[Prompt]`。

### 3.3 负面提示词 = 三类名词清单（顿号分隔，不含动词）
`技术缺陷`（低清晰度、模糊、噪点、过曝、色彩溢出、塑料质感）＋ `内容禁区`（文字、数字、字母、Logo、水印、字幕、人物）＋ `结构一致性`（变形、断裂、透视错误、重复车辆、穿模、闪烁、画面跳切）`[8/8 负面块均落这三类]`

### 3.4 图生视频（有素材时）
先 S3 取真实高清图 → 当首帧 → 视频提示词里声明「严格保持首帧画面的视觉风格/透视/物体位置不变，只让 X 运动」。
循环类（适合 PPT 背景）：写「循环补位/往返/持续输送」，并要求「最后画面与首帧一致」 `[Deck：整页视频 mediacall 2128 次是主力手法]`

### 3.5 动图（GIF）提示词 = 六段式
`[来源交底]` 语料的 49 个真实提示词块里没有独立的"动图块"（那 49 块是文生图与图生视频），
这一节是**从 161 个 GIF 的物理特征反推的写法**：帧数（最少 24、中位 51）、尺寸
（426x240 / 1138x640 / 800x800 最常见）、以及它们在模板里的用法（开场划过、水墨晕开、扇子/卷轴旋转）。
六段：① **参考图声明**（附件1 只作构图与色域依据）② **全局参数**（尺寸、时长 3–6 秒、帧率）
③ **循环声明**（首尾帧一致、无缝循环，不许播一次就停）④ **秒级分镜**（一个元素一条运动线）
⑤ **运动约束**（元素之外全部静止，不出现镜头推拉）⑥ **背景与叠加**（透明底或纯黑底，
方便叠在蒙版之上；不得自带文字与边框）。判据：G2 按 6/6 段与≥300 字核，G11 按真帧数核。
**底色必须透明**：本机 `scripts/make_gif.py` 产出带透明索引的循环动图（`arc/sweep/bloom/spin` 四种动效、
`gold/ink/cyan` 三种色相）；不透明底 GIF 叠在矢量色场页上会露出一块方框（渲染实测），G11 直接拦。

## 4. 技法库（必须内置，不许只写理念）

`kb/deck_tech.json`，每张卡字段：`id, 何时用, 操作步骤(点击级), 具体参数(数值), OOXML 写法, 对应闸, 来源证据`。
最低覆盖（全部来自本次实测）：
- 转场：`fade` 213 次、`morph byObject` 192 次（dur 2000ms, spd=slow）、`blinds` 35、`checker` 10、`prism` 8、`sndAc` 音效 104 次 `[Deck]`

## 5. 素材爬取规范
- **通道 3：Openverse（`fetch --source openverse`，2026-11-07 加）**——
  `https://api.openverse.org/v1/images/?q=`（不带 license 参数：实测带 `by,by-sa,cc0,pdm` 这种
  逗号多值时 `result_count=0`，所以改成回来源按许可白名单逐条筛），匿名可调（有速率上限，
  设 `CAOFENG_OPENVERSE_TOKEN` 走 Bearer）。返回 `width/height/license/license_version/creator/url/
  foreign_landing_url`，许可拼成 `CC BY 2.0` 这种可举证写法，与 Commons 同一套安全筛、相关度筛、
  短边筛与"同一 URL ≤3 页"轮换。加它的原因不是贪多，是实测供给：231 页的册子按
  短边≥1080 + 相关度≥50% + 非档案照三条筛完，Commons 单源只够 58 页（25%），
  整册七成页只能走色场——那是被供给卡住，不是被判据放过。`--source auto` = 两路都查、
  候选合并后一起过筛，判据一条不降。
  2026-11-07 实测的四条 API 边界（都写进了代码，不靠记忆）：
  ① **匿名 `page_size` 上限 20**，填 21/50 直接 401「page_size may not exceed 20 for anonymous
  requests」，所以候选池要 40 条只能翻页拿（实测同一词一页 19 条、两页 29 条）；
  ② **多词是 AND 语义**，4 词短语整批 0 命中而前 3 词有货，所以退词必须**按源各自生效**——
  旧写法把两源合并后只看总结果是否为空，Commons 一命中，Openverse 那条长词组就永远轮不到
  重试（v5 覆盖因此停在 61/231，缺口日志清一色"最高相关度仅 0%"）；
  ③ **短边筛要在源头做**：`&size=large` 是 Openverse 自己的像素档，实测 'doctor consultation
  room' 不带参数 19 条里短边≥1080 的 0 条、带 large 的 19 条里 18 条达标（`fetch` 在
  `--min-edge ≥1080` 时自动带上这一档；门槛低于 1080 时不强加，免得把中图池整批丢掉）；
  ④ **`thumbnail` 字段不能拿来下载**：它指向 `api.openverse.org/v1/images/<id>/thumb` 转发口，
  实测拿它下整页素材回 HTTP 424 Failed Dependency；`rendition` 改为按 Commons 路径规则自拼
  `thumb.wikimedia.org/.../3840px-<名>`（Wikimedia 现在只放行尺寸白名单，3200px 实测回 400
  "Use thumbnail sizes listed on https://w.wiki/GHai"，3840px 可用），拼不出就用原图直链，
  同一个文件实测从 3,182,827 字节降到 1,513,979 字节、仍是 3840x2880。

- **档案照要两道网，而且验收端必须重量一次**（2026-11-07 实测漏网）：公共领域/CC 的老照片在字段上
  全绿——`Minidoka Relocation Center … Laboratory technician … - NARA - 536550.jpg`
  的许可是 Public domain、相关度 100%、短边 3000px，却是一张二战日裔关押营黑白照，
  对外路演放上就是错的主题与色调。所以判据是两道：① 来源标记词（`NARA / national archives /
  relocation center / internment camp / world war / WWII / 逗号 + 四位旧年份`）；
  ② 像素彩度（平均彩度 <12 **且** 彩度>30 的像素占比 <0.15% 才算黑白——只看平均值会误杀夜景、医院前台这类色调安静的现代片，实测 104 张里误杀 15 张）。**只有 fetch 判不算数**：manifest 是历史累积的，
  `check` 必须对现文件重量像素、重跑一次标题筛（实测这一条拦下 7 条标题 + 22 张灰度成品图）。
  收紧判据时正反用例一起进 `test_safety.py`（现在 19 拦 / 10 放），不许只改代码。
- 渠道优先级：① 国内可直连的 free 许可站与官方图库；② Wikimedia Commons（CC 许可，可举证）；③ 国外站点（走 7897）；④ 企业官网公开图（标注来源）。
- 每条必存：url、页面标题、许可声明原文、下载时间、SHA1。
- 质检（全部机器执行，且量的是**成品里的字节/像素**，不是 manifest 里当初抓到的数字）：
  短边 ≥1920 的原图 + 内嵌后仍 ≥1080；许可非空；非纯色；宽高比适配目标版式（16:9 底图 / 4:3 卡片 / 1:1 图标）；
  视频页的 mp4 分辨率 ≥1080 且第 0 帧必须与首帧参考图是同一画面（实测平均绝对差 ≤28/255）。
  **（2026-11-09 更新，判据唯一定义点在 §19，本节只留历史与三道真实约束）**这一条早期写的是
  "渲染页与网图的水印/烧字自动检测本机做不到"（实测：右下角边缘密度既会把带「AI生成」的页判成正常，
  又会把矢量色场页判成异常），当时只有三道软约束：留白区避开右下角、封面优先走即梦、
  交付前必须人眼看 `shots` 拼图（G12 强制真渲染就是为这一步服务）。
  **现在本机确实有了检测器**（§19 的时序叠加层检测 + 水印模板匹配 + `G28` 闸，pickup 认领时自动跑），
  所以那句"不许在文档里声称有检测器"作废；但它的教训保留且升级为 §19 的三条禁止假绿：
  "检测器没报=干净"、"补后再匹配"、"低阈值把场景亮边当水印"——三条都实测假绿过，一律不作验收口径。
  网图这一路仍不吃 §19 的模板（没有原件可抠），由 G3 的许可/来源/相关度拦。
  （2026-11-08 补：能拦的只有 gen/ 投放产物那一路——提示词本就要求无文字无水印，角区出现
  字形笔画基本只剩平台角标一种解释，由 §7 G28 量右下角角区拦；渲染页与网图仍靠人眼。）
- **CC 授权 ≠ 无标记**（2026-11-05 实测）：Commons 的摄影作品常把作者签名烧在画面里
  （例：浦东夜景原图顶部有「2018© D&J Photography」）。这不是图库水印，许可上完全合法，
  但对外片子上就是杂物——只能靠 `shots` 人眼发现，然后**裁掉那条边**：裁完必须同步更新
  manifest 的 `sha1/bytes` 与 `stored_w/stored_h`（`w/h` 仍记抓到的原图尺寸，SPEC §5 的 ≥1920 判据看的是原图），
  否则 G3 的字节复算会把它判成"素材被偷换"。
- **档案照与信息图不算实景**（2026-11-06 目检发现）：Commons 里 `data center` 会命中 1970 年代氧气厂
  开关柜黑白照、`clinic reception` 命中 1940 年代煤矿公司前台、`data center` 相关词还会命中
  「美国数据中心分布图」这类信息图。`safety.is_archival()` 按全大写标题、`Historic American`、
  `United States`/`USGS`/`geologic`、"Company, X County"、年代（18xx/19xx）拦掉；
  **不含 diagram/infographic 字样**——软件架构图、组织流程图是合规技术插图，
  safety 用例里「Software architecture diagram」必须放行（加过这两个词，就被这条用例打回过一次）；
  fetch 与 G3 两端都复筛。实测拦 4 张档案/信息图、放行 4 张当代实景（服务器机房、诊所前台、长沙夜景、救护车内饰）。
- 硬底线：拿不到许可就降级为「自绘矢量色场」，绝不用疑似盗版图，绝不伪造来源。
- **下载取 3200 rendition，不搬原图**（`iiurlwidth=RENDER_LONG_EDGE`）：原图实测 8–21MB，
  每页要多等 60–90 秒，而装配本来就只留长边 3200。manifest 的 `url` 仍指原文件（许可与来源以它举证），
  判"原图短边 ≥1920"用的是 API 回的原图 `w/h`，不是这张缩样。
- **限流不是"没素材"**（2026-11-06 实测）：一口气取 106 页时 40 页吃到 `HTTP 429`，被写成 gaps，
  真素材覆盖率掉到 13.8%。现在 `http_get` 对 429/503 退避重试（6/12/18 秒），两次请求之间强制间隔
  `GET_MIN_INTERVAL` 2.2 秒；重试耗尽仍失败才记 gap，并在 gaps 的 why 里写明是限流而不是没货。

## 6. 模型路由

| 需求 | 通道 | 备注 |
|---|---|---|
| 静帧背景/插图 | **即梦「图片生成」网页版**（人工一键，免费额度） | **禁止用 Qoder 自带 ImageGen**：消耗用户模型积分，且右下角烧「AI生成」水印。整页背景要 16:9 **高清/2K 档**（短边 ≥1080），否则装配自动降级成矢量色场 |
| 零手动的静帧替代 | S3 联网抓 CC 授权真实照片（全自动、可举证） | 国外走 7897，国内直连 |
| 高清参考图 | S3 联网爬取 | 直连或 7897 |
| 图生视频/首尾帧视频 | **即梦/豆包网页版**（人工一键） `delivery_card` 给点击步骤 | 用户已确认用免费额度网页版 |
| 动图(GIF/短动画) | 即梦「图片动画」，或本机 `scripts/make_gif.py`（透明索引循环动图：arc/sweep/bloom/spin × gold/ink/cyan） | 无需外部模型；**不透明底不许叠在矢量色场上**（G11 拦） |
| 口播/配音 | 未取到本机能力 → 标「未做」 | 不许假称支持 |

装配写法（S6）：
1. 视频整页背景：`p:pic` + `a:blipFill` 全屏，`p:timing` 用 `tmRoot→mainSeq` 播 media；自动播放用 `stCondLst delay="0"`，点击播用 `interactiveSeq` + `cmd mediaRew/playFrom` `[Deck 实测结构]`
2. 平滑运镜：相邻页同名同 shape id（`p159:morph option="byObject"` + `p14:dur="2000"` + `mc:Fallback` 里 `p:fade`）`[Deck]`
3. 蒙版：图片上层加 `a:gradFill`/`a:solidFill` + `a:alpha`，压暗幅度按 G4 计算
4. 文字层只允许落在提示词声明的留白区内（G5 用几何求交判定）

- **G4 背景怎么取（2026-11-07 修正）**：渲染像素里，"背景"= 文字框内**不属于本页任何字色**的像素取中位。
  以前只剔这一框自己的字色，于是同一页上的青色大数字、别的白字的抗锯齿边都被当成背景，
  实测深色底上的白字被量成 1.64:1（真值 >10:1），改判据后同一册从 21 框降到 8 框。
  配套的两条工程改动：① 矢量色场自画的母题（柱/同心圆）亮度压到 ≤0.14，不许比白字还亮；
  ② 蒙版厚度按"文字落点区实测亮度"反推（`scrim_alpha_for`，55%–90%），不再固定 62%。

## 11. 同级标准（语料实测口径，2026-11-06 二次挖掘）

实测来源：`kb/data_design.json`（835 张好示范页逐页量几何与字号）、`kb/table_design.json`
（语料里真正带 `<a:tbl>` 的 22 页，来自 4 套模板）、`CAOFENG_WORK/tutorials`
（用户新投喂的 24 条教程视频：场景采样帧 + tesseract 屏幕文字 + faster-whisper 逐句讲解）。

## 12. 提炼契约（取代"逐字上屏"）

三条硬规定加一条读得通规定，全部可机检：

1. **提炼上屏**：每页由 agent 写 `headline`（≤16 字）、`display_lines`（≤2 条、每条 ≤14 字）、
   可选 `hero_number`（数字 + 单位 + 一句结论）。显示文字允许改写、允许压缩。
2. **事实可溯**：显示文字里出现的每个数字、百分比、金额、专名都必须在源文档逐字出现（G1 保留并加强）。
   改写措辞自由，编造或推导数字自由——都不自由。
3. **逐段覆盖**：源文档每个段落（≥20 字）的"事实单元"（数字 / 专名 / 金额 / 比例 / 时间）
   至少出现在一页上（G24）。段落被压成短句不算丢内容；事实单元消失才算丢。
4. **显示行读得通**：区间是一个整体事实（`1280 到 1980 元` 整条上屏，不拆成两个裸数）；
   章节序号粘数字的窗口碎片（`二·1280`）不许上屏。`refine` 不覆盖已有提案，所以装配端
   （`place_text`）必须兜底丢碎片、补区间；自测对计划侧与装配端做双检差分。

例外与开关：

- **台账例外**：源文档里的表格必须逐格进成品（G13 的表格分支保留），但版式按 G25 重新设计。
- **`plan --verbatim`**：需要"正文一字不删"的全量册时用它，保留旧的逐句上屏模式；
  此时 G22 同级分与 G23 页面预算豁免，报告必须写明"这是全量留档册，不是发布会册"。
  两种产物不可能同时满足，SPEC 把这句话写死，免得 agent 又去两头糊。

**事实的载体顺序**（2026-11-07 按语料现测定的，不是审美偏好）：语料随机 6 套 / 40 页里
"单行字数 p50=4、p90=12"、"每页文本行数 p50=5"——模板是一页很多短文本框，不是一页两三句长话。
所以同一页里事实按这个顺序找载体，越靠前越省字数：

1. `hero_number`（一个 110pt 级大数字 + ≤8 字结论标签）；
2. `bar_group` / `card_grid`（同单位对比、并列要点）；
3. **筹码行 `chip_strip`**：版式没画掉、但 G24 要求必须上屏的事实，改成 ≤3 个短筹码
   （每个 ≤12 字），而不是把整句打回正文——实测 3 个事实约 30 字，比一句 14 字 × 2 行更省且更像模板；
4. 最后才是 `display_lines` 正文短句（≤2 条 × ≤14 字）。

**一把尺子（2026-11-07 定，`display_refine.fact_units / series_groups / budget_units`）**：
“这一页装不装得下”必须由同一个函数回答三处——分页预算（`chunk_body`）、提案装箱
（`propose_lines`）、验收（G24）。上一版三处各写各的正则：G24 数“数字+专名”、提案只数数字、
分页只数数字，于是一页“履约率 79.9% / 潜在池 412 家 / 转化 96 家 / 曾合作医美”被引擎判为合格，
成品上 `96` 与 `曾合作医美` 双双消失（v9 实测缺 32 个事实）。配套三条硬规则：

- **一组并列数值只占一个版面名额**：同单位 ≥3 个数值（四个城市、四个季度）在语料里是四根柱子，
  不是一个显示行——`series_groups` 把它们折成 1 个名额，装配用 `bar_group` 一次画完，数字落在条顶、
  专名落在柱底。上一版按数字逐个算预算，把一组柱子从中间拆成四页，条形组的 ≥3 条件再也不成立
  （成品图形化率 0.019 / 语料中位 0.163）。一页最多一组、一组最多四根（`bar_group` 上限），超了继续拆页。
- **装不下就拆页，不许删事实**：`split_by_facts` 在 plan 阶段按子句把超载页拆开重排，
  拆完重新提案；单个子句本身就超载时保留 `display_needs_edit`，交给 refine/agent 重写，闸门继续咬。
- **标题让位给柱子时只剥数字**：把含系列数值的子句压成“这个词”（`单店月均出货 38 万元` →
  `单店月均出货`），既不让 `52万元` 在标题和条顶各打一遍，也不许拿 `clean_label` 把
  `单车年收入` 剥成 `年收入`（专名就核不到了）；只取第一个站得住的说法当标题，
  不把残句用逗号拼起来（`第一季度投放，第二季度` 读不通且与柱底标签重复）。

重影一律拦：与标题同义的行不上屏；大数字只画"标题里没说过的那一个数"，而且只能从**正文**取数
（从标题取就会把 `2026` 放大 150pt 又在下面原样打一遍标题）；大数字要把紧跟的数字后的量词一起放大
（`412` 挂成裸数字就是"412 什么？"，实测页 5）；条形组画掉的那几行不再回正文，`keep` 只补
屏幕上确实没有的那几条（实测 `'客单价1240元'` 因 keep 与 body 撞车打了两遍）；
柱底标签不许用编号占位（`成本` 被 `VERB_PREFIX` 剥空后写成 `第2项` 是缺陷不是省字）。
标签要么是词（≥2 个非数字字符）、要么不画，实测出现过 `hero_label='1'`（千分位逗号被当断点）
与 `'281.4万元'`（把标题里的另一个数当标签）两种。
探针册（10 页合成 docx）实测这条顺序把每页字数 p50 从 43 字压到 12 字、G8 孤字尾行清零、
图形化率 0.019→0.375（语料中位 0.163）、三句四值系列的册子 3/7 页真画出柱子且 G24 缺 0。

**散文页与"标题里就一个数"（2026-11-07 v10 实测补齐，四条都进 `test_gates.py`）**

v10（238 页真册）暴露的三类漏法与对策，口径都落在 `display_refine` + `place_text`，不在提示词里许愿：

1. `display_refine.parallel_enum`：并列的一串（≥3 条、每条 ≤12 字、按公因子分组取覆盖最大的一组）
   画成卡片（`display_lines_source='enum-cards'` → `data_layout='cards'`）。
   总起句（它就是标题）不含公因子，不会被算进组里，也不会因此否掉整组。
   散文（'道理不复杂，先把车交给医院，再由医院排期…'）没有 ≥2 字公因子共串，测出来是空。
2. `display_refine.clause_pack`：其余散文**只在子句边界**装箱成 ≤2 条 ≤14 字
   （`display_lines_source='clause-packed'`）；单条子句本身超长的整条不上屏，
   它里面的事实由末尾事实安全网补回。绝不退回"整段原话小字墙"（v10 有 15 页 86 字就是这么超的）。
3. `caofeng.headline_hero`：陈述页的标题里恰好一个带单位的数（'盈亏平衡 9.0 台'），
   就拆成 标签（'盈亏平衡'）+ 超大数字（9.0 台），与语料那种 statement 页一致。
   四个前提缺一就不动：整页正文与标题同句、恰好一个数（两个数是"从 A 到 B"，不拆）、
   不是裸年份、去掉数字后的词仍读得通（≥3 字且不挂在介词上）、留白区 ≥0.52 画布高（画得下才摘）。
4. `caofeng.table_pages`：台账翻页按**字预算**也按行数（每页 ≤`page_chars_max_table`×0.72，
   且 ≤`MAX_TABLE_ROWS`=8 行），一行 70 字的出处表不再 8 行硬挤一页（569 字 > 上限 400）。
   行数与单元格一个都不许少——G13 的逐格核对是这条的刹车。

配套口径修正（同一把尺子，别各算各的）：

排版宽度也只许有一把尺子：`data_layout.char_em_width`（CJK/全角 **1.08 em**、半角 0.60、
`.`/`，`0.32、`%` 0.92、空格 0.38）。1.08 不是抄来的系数，是对着 WPS 真渲染反推的：
17 个字的 24pt 标题在 0.425 画布宽的框里按 1.0 em 算"正好一行"，实际把最后一个字甩到了第二行

**G20 与 G23 只量"装配页"**。片尾的来源署名页是

**构图骨架（2026-11-07 用户第七轮否决"整体布局和目标相差太远"后重做）**

闸全绿、同级分 88.7 仍然被否：渲染出来是"左上小标题＋右半小图框＋下半页空渐变"。
对照 `kb/layout_archetypes.json` 的实测，差在四条骨架，现已写进装配：

1. **图是主角**：语料 60.8% 的页图占满/出血（pure-visual 33.5%＋full-bleed 27.3%），分栏只占 22.7%。

   （语料 full-bleed 压字率 99.2%）。照片按框居中裁切填满（srcRect），不再留letterbox 小框。
2. **字号阶梯按版式给**：语料每类版式最大字中位 split 80 / full-bleed 66 / 陈述 180 / text-block 30。

4. **表格铺满**：行高按留白区摊满（0.45–1.10 英寸，语料中位 1.10），表头 20pt/正文 16pt（语料中位），

1. `pack` 生成 `delivery_card.md` 后必须**把卡片全文打到 stdout**（agent 只要跑了 pack 就一定会看到全文），

2. `build` 发现有"要 AI 产物但没有产物"的页时：不静默降级、不用色场蒙混，而是打印固定话术

## 14. 取图通道加 Unsplash

用户给的通道原文：**官网 https://unsplash.com（可切换中文），搜索关键词/颜色/分类，hover 点 ↓ 下载；
注册可建收藏夹/上传作品（每周限 10 张起）。**

实测与实现口径：

- 本机直连与走代理 7897 抓 `unsplash.com/napi/search/photos` 与 `unsplash.com/s/photos/<kw>`
  都返回 **HTTP 401**（需要登录/令牌），所以"全自动下载"只在有官方 API 密钥时成立：
  环境变量 `UNSPLASH_ACCESS_KEY` 存在时启用 `fetch --source unsplash`（记 url、许可、作者、下载时间、SHA1）。
- 没有密钥时的合法路径（默认）：`delivery_card` 为每页给出 **Unsplash 检索 URL**（关键词 + 颜色 + 分类）
  与点击级下载步骤，用户下载后放回 `materials/`，再用
  `fetch --adopt <文件> --source unsplash --page N` 登记来源与许可（不许裸文件进成品）。
- 许可差异要交代清楚：Unsplash License **不强制署名**，CC0 也不强制，CC BY / CC BY-SA 强制。
  因此"图片来源"页的数量由素材构成决定；用户要求"零来源行"时，替换路径是
  Unsplash / CC0 / 自绘矢量色场 / AI 定制造型，而不是偷偷删署名（G3 统计并输出各许可的页数）。

### 16.1 目检抓出来的四类"分数看不见"的缺陷（必须一起守住）

同级尺量的是形状尺寸与字数，量不出内容是否读得通。真渲染逐页目检抓到四类，
每一类都已沉淀成机器闸或装配规则：

1. **假图表**（v10 页 20/58）：'500 名女性'、'300 人'、'500 台' 被并成同族三根柱子，
   或公告参数（7 米 / 12 座 / 5070mm / 385mm）画成对比图——数字之间没有可比性，
   图比文字更像假数据。规则：`items_from_numbers` 只在**每条都有类别名**
   （`is_category_label`：2–6 字、不含动词虚词、不以量词开头）且最大/最小 ≤25 倍时才出组；
   出不了组就退回大数字/筹码/短句。闸：G8 `naked_charts`（≥3 根柱而柱底类别名 <3 判不合格）。
2. **断头数字**（v10 页 89）：标题硬截在数字中间，屏幕上是 '这是一篇覆盖 82'，
   原文 '82,340 例'。规则：`repair_head_number` 用原文把前缀补回完整数字并带上紧跟的量词。
   闸：G24 `truncated`（逐页比屏幕数字与原文数字，屏幕串是原文串的真前缀即判不合格；
   全簿文本核看不见这一类，因为完整那串在别的页出现过）。
3. **断头词**（v10 页 14/48）：字数预算硬截把定语切成 '50 多家分娩量太'、'一年服务 18,000 名女'。
   规则：`_short_label` 切在中文中间时退回最后一个"数字+单位"；筹码标签只接受词边界上的
   类别名（数字后那截后面还跟着中文字就丢弃）。
4. **裸数筹码**（v10 页 20/48/58）：'500'、'15' 单独上屏，读者不知道是什么。
   规则：事实挑子句按"能不能说明这个数"打分取最优子句（不再取最短子句），
   数字优先带原文紧跟的量词（'500 名女性'），其次带类别名（'主动说 18.9%'）。

不许用的歪路：改尺子（基线/权重/度量函数）凑分、把文字藏进不可见形状、给每页塞假图、
把不可比的数字画成图、用断头词换字数指标。
**"改尺子凑分"指放松尺子让坏成品过关**；按用户指令把非模版元素剔出基线（2026-11-11）是相反方向——
它让尺子更严、当前测试册分数下降，且仍能把语料好示范判达标、把 junk/文字墙判不达标
（`test_gates` 差分自证）。判断是不是歪路看两条：尺子有没有变松、好坏两端还分不分得开。
每一轮改完必须：build → check（不渲染先跑数）→ deck_parity 复量 → 六维 attain 单调不降；
全部 1.0 后才跑 `--render` 逐页目检收口，目检发现的缺陷按上面四类归并成规则+闸，再回炉。

### 18.4 教程操作的机器闸补账（2026-11-10 干净上下文审计，P17）
审计查实 §18.1/§18.2 宣称落地的几个操作"代码写了、没有任何闸读过"（零闸死账），逐条补上判据+反证：

  「播一遍就停」。反证：把属性改成 `repeatCount="1"` 必被拦。v10 真交付 9/9 页基线全带。
- **标题与上一动画同时**：G18 对 cover/divider/closing 视频页（有入场形状）要求 `nodeType="withEffect"`
  计数 ≥1，为 0＝硬伤「标题排在视频之后才出现」。数据页走语料 preset 阶梯，不在此列（尺子与承诺同范围）。
  反证：withEffect 全改 afterEffect 必被拦。

## 19. 漂移水印的真删除链（2026-11-09 用户回件 1080p 封面视频实测）

免费档豆包/即梦视频水印不是"右下角固定角标"：实测同一段 8.06s 视频里，"豆包 AI 生成"
0–3.7s 在**右下**、4s 附近**淡出**、4.4–7.5s 在**左上**、7.6–8.06s 溶解成带红青描边的彩色块。
老的"抽 16 帧看右下角"与"逐帧角区 TELEA"两条都对不上这种走法（前者漏、后者把场景彩色
辉光当水印补成黑疤）。以下五条是机器可核对的契约，实现点 `scripts/lama_cleaner.py`。

1. **叠加层自证判据（三条同时成立才算水印）**：① 单帧 31 核空间中值估背景后的正残差
   （细笔画被中值抹掉、宽辉光保留）；② 15 帧窗口内的持续性（>=30% 帧残差>=10，镜头
   运动带来的高光边平均掉）；③ 中性亮色（色度 max-min<=45 且亮度>=85）。
   实测该尺子把水印（色度 16–36、窗口残差 15–46）与场景蓝光点（色度 53–113、残差 19–43）
   分开——**只用量级分不开，必须上色度**。
2. **逐帧精修只在该帧自己的脚印内做**：窗口框并到全片会让相机摇移后"当时并没有水印"的
   区域被误补（实测把 t=4.5s 的干净背景补成可见灰疤，残差像素从 17 万涨到 121 万）。
3. **模板匹配是权威签名，"检测器没报"不算干净**：水印位图固定，从最清晰帧的窗口并集框内
   抠残差二值图当模板（`build_wm_template`；只取单个分量或把角区光条混进模板都会让匹配失效，
   实测踩过）。逐帧四角 `matchTemplate`，命中且框内有中性亮笔画才算脏帧。
   **假绿灯教训（用户实测第 2/3 页仍带水印）**：① "窗口检测器没报=干净"漏掉淡入中的半透明
   水印；② "补完再匹配"对半行残字匹配分低于阈值又放过。两条都不能当验收。
4. **裁角优先（视频）**：免费档水印只落在四角带内，`crop_out_corner_watermark` 物理裁中央
   16:9 再放大——零残留零补痕，验收用**几何证明**（每个确认水印框都在裁切矩形外）+ 高阈值
   (0.45) 模板匹配双保险。裁切带按确认框（中性色+pers>=15）自适应、封顶 320px，放大倍率如实
   写进返回值（实测 1.69x）。逐帧 LaMa 补只作图像侧与补得干净时的选项，不再作视频主路线。
5. **无缝循环与首帧自洽**：保留段做正放+倒放（`ping_pong`）后循环处零跳帧；页面首帧参考图
   按语料"封面用视频自己的帧"换成成片第 0 帧（`refresh_still_from_video`），否则 G15 会
   如实报"poster 与视频第 0 帧不是同一个画面"。AI产物 里的原件不动，溯源仍按原件核。

**判据只有一个定义点**：G28 视频侧改为"拿 AI产物 原件抠的水印模板逐帧匹配成品"（>=0.45 命中
>=3 帧才拦）；角区启发式在裁角后的片子上会把进角区的亮边误报成角标（实测 12/12 假报），
只在拿不到原件/模板时兜底。验收口径：`clean_cover_video` 返回 `clean=True`（几何证明通过 +
高阈值模板零命中）且 `loop_seconds` 落在 G6 的 5–10s；实测三条回件各 ~25s 完成
（ProPainter 全帧路线在同机 78 分钟未吐一帧，仅保留为 `--deep` 挂机选项）。

## 20. 主体直写与首帧唯一性（2026-11-09 用户"为何一直重复发提示词"查实）

**用户看到的重复不是错觉，是引擎缺陷。** 三条实测证据：
1. 旧 `image_prompt` 模板把主体写成"画面中央偏下设置**与「章节名」直接相关的核心视觉主体**"，
   在册 230 张图卡里 **211 张**是这种间接话；
2. 间接话让主体槽退化成标题/实体词，**101 页的主体特征逐字相同**（模型必然出同一类图）；
3. 20 个过渡页的"首帧附件"全指到 `out/bg_fallback/pNNN.jpg`，两两像素差 **0.07–1.7**
   （同一张深蓝渐变，均色 (6,38,64)），而视频提示词正文除路径外逐字相同。

连带查实两个问题：第 3 页（章节 01 的数据页）装的视频里**烧进一个巨大"02"**（数据页本不该
挂整页视频，语料只有封面/隔页动）；G15 的首帧一致性尺子被封面规则顶平——
`refresh_still_from_video` 把 `gen/pNNN/image.png` 换成视频自己的第 0 帧，于是 MAD 恒≈0
（报告写 mad 1.0/1.04/0.99），"02"与"20 页同一张"都拦不住。

**引擎改法（全部可机检）**：
- `styles.looks_visual(subject)`：主体句必须带画面/量词开头才算"能直接画"；否则
  `styles.concrete_subject(role, headline, entities, subject, body)` 按语料句式翻成具体画面——
  物件从 `OBJ_KEYS`（医疗车/门诊楼/女性健康诊室/账本电脑/数据柱/城市路网/三角网络/岗位环/
  风险挡板/年轮刻度/闲置库房车/被封岔路/附录书页…）按页面实体命中，构图从 `ROLE_FRAME` 按角色命中，
  象征句取本页标题剥掉序号头后的第一个完整短语（实测"三，车日服务费…"会被切成"象征三"，
  两页因此逐字相同）。语料原话就是直陈式（"画面中央是一支巨大的向上指引箭头，由明亮的青蓝色
  半透明能量光束构成…象征突破、增长"），本节的句式以此为锚，不是自创。
- `image_prompt/video_prompt` 模板**直写主体**：`主体特征：{subj}。主体占画面宽度约 22%…`；
  第一行"主题为「…」"改用短标签（本页标题前 14 字），不再把整句场景塞进书名号。
- `validate_prompts` 加两条硬判据：主体特征出现"与「…」直接相关的核心视觉主体"即拦（模板回退就报错）；
  两页主体特征逐字相同即拦（两页必然同一张图）。
- `card_first_frame(work, page)` 是**首帧附件的唯一口径**：只认这一页专属静帧
  （gen 出图 → manifest 里验收过的 materials），**公共色场不算**；`sync_card_attachments` 在
  `pack` 里按现状重写卡上的附件句（实测一次重指 23 张），卡与闸读同一份文本，不再手工改 promptpack；
  没有专属静帧的页由 `card` 自动把文生图加进必还清单，并打印"这一页还没有专属静帧…先出图再当首帧"。
- G15 的尺子改成"用户当时被要求上传的那张原件"：取值顺序 `video_source.json['attachment']`
  （pickup 现在会记）→ 卡上点名的路径 → `card_first_frame`；两页首帧附件像素差
  <`attach_distinct_min`(=12) 直接拦；尺子等于被替换过的 poster 且没有凭证时报
  "量不出结果"（现在如实红在页 1/2，这是交底不是放行）。

**实测收口数字**（同一份 `validate_prompts` 前后对比）：在册 213 张图卡的间接句式 **211 → 0**，

## 22. 取图贴合度闭环（2026-11-10 用户问"能搜到完全贴合的图吗"）

**美学闸 `photo_style_reason`**（stock 下载后必过，G3 装配前再核一遍 `style_bad`）：
- 离色板饱和像素 >25% 拒（按所选风格色相窗，**键必须是 `corpus_tables.PALETTES` 的真色板 id**：
  tech_blue 185–255°、neon_cyan 165–265°、party_red 335–395°；ink_wash / business_light / photo_real
  不吃色相窗，只查杂乱与过曝——写成 'neon'/'white_biz'/'warm_gold' 会静默落进蓝窗默认值，
  等于拿 tech_blue 的尺子判另外三种风格）；
- 边缘密度 >0.035 拒（背景要干净舞台感，纪实场景杂乱）；
- 平均亮度 >0.5 拒（白昼照压不住白字）。
**实测标定**：用户即梦电影级底图色板符合度 0.93–0.996、边缘 0.015–0.021、亮度 0.23–0.37；
纪实 stock 边缘 0.024–0.059 或离色板饱和像素一大片——分离度足够做闸。
stock 全拒的页**不降色场凑数**，回文生图投放卡（高级感优先）；确需真实举证又不过闸的，
报告如实标「降级交付_纪实配图」。反证进 test_gates：黄杂图拒、蓝 glow 图放行。

## 25. 提示词主题/象征句必须是完整短语（2026-11-10 用户："这些图片都这么低级…继续完善"后的自查）

**问题**：自动生成的主体句被缓存后跨轮复用，原料（上屏行/标题）改了旧句不重算；
路演体半句话标题被直接截进提示词，出过「主题为「七」」「象征第6章那套混编采购口径会把投」
「象征整车含上屏行尾巴粘的 ·16 序号碎片」这类一眼坏掉的句子——投放卡质量就是成品质量。
**硬判据（尺子在 styles.py `clean_phrase`/`phrase_ok`，scaffold 生成与 pack/check 复核共用同一份）**：
- scaffold 每轮**重算**自动主体（shots.json `subject_auto=true` 标记的句子不复用；agent 手写的主体原样尊重）；
- 主题按 上屏行→章节名→标题→deck 标题 逐级清洗验收，象征句按 上屏行→正文首句→标题 验收；
  合格＝完整短语：≥4 字、不以虚词收尾（的了把是会投持…到）、非纯数字/单字序号、
  去掉 `·数字(单位)` 序号粘数字碎片；整句洗不出合格短语就**省略象征句**，绝不硬截塞半句话；
- 视频提示词里嵌的「X」主题与静帧共用同一个 `_theme`（旧代码 `headline[:14]` 硬截是漏网调用方，
  实测写出过「「一句话」主题 PPT 动态背景视频」配「主题为「车联体商业计划书」」的双口径）；
- `validate_prompts`（pack 写账、G2 复核）对落盘提示词再量一遍：「主题为「X」」或「象征Y」
  不过尺子判不合格，手工把半句话改回提示词文件也会被拦。
**反证进 test_gates**：14 例短语判据好坏对照＋「合格卡塞回 主题为「七」/半句话象征 必被
validate_prompts 拦、还原即放行」。
