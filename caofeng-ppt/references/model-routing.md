# 模型路由与投放（豆包 / 即梦 网页版）

## 能力矩阵（本机实测事实）

| 需求 | 走哪条 | 是否自动 | 备注 |
|---|---|---|---|
| 文生图（静帧背景、插图） | **即梦「图片生成」网页版**（人工一键，免费额度） | **禁用 Qoder ImageGen**：消耗用户模型积分 + 烧「AI生成」水印 |
| 静帧的全自动替代 | S3 联网抓 CC 授权真实照片 | 全自动、可举证；抓不到就降级矢量色场 |

| 高清真实照片 | 联网爬取（见 material-sourcing） | 全自动 | Commons 走代理 7897 |
| 图生图 / 风格迁移 | 即梦网页版 | 人工粘贴 | 用户已确认用免费额度 |
| 文生视频 | 即梦网页版「视频生成」 | 人工粘贴 | 本机无视频模型 |
| **图生视频（首帧/首尾帧）** | 即梦网页版「视频生成 + 上传参考图」 | 人工粘贴 | **优先这条，最贴语料做法** |
| 动图 GIF（元素动效：水墨晕开/扇子/卷轴/闪光划过） | 即梦「图片动画/循环动图」，或本机 ffmpeg + Pillow 抽帧合成 | 半自动 | 语料 161 个 GIF 的正规做法；单帧不算动图 |
| Ken Burns 平移缩放（静图当"伪视频"背景） | 本机 ffmpeg + Pillow | 全自动 | 无需外部服务，但没有真元素运动 |

| 口播 / 配音 | 本机无可举证能力 | — | **标"未做"，不许假称支持** |

## 整页背景要够 1080p（内嵌地板）

装配的内嵌地板是**短边 ≥1080**（`TH['embed_short_edge']`）：短边不够时 `build` 不会硬报错，而是
**自动把该页降级成矢量色场**（画面里没有实景），并在 build_log 写明原因。所以：

- **即梦出图**：选 16:9 + 高清/2K 档（2K 档一般给到 2048x1152 及以上，短边 ≥1080 直接过）。
  低档位（1024 级）出的图只能当局部插图或图生视频的参考图。
- **联网抓图**：Commons 原图普遍 3000–8000px，`normalize_asset` 压到长边 3200 后短边仍有 1800，天然达标。
- **禁止用 ImageGen 凑**：它的 16:9 档只有 1792x1024（短边 1024 过不了闸），更要紧的是它消耗用户的模型积分
  并烧「AI生成」水印——本技能不允许调用它（SKILL 硬约束 6）。

回收后统一走 `python -c "import caofeng as C; C.normalize_asset(src, dst, crop169=True)"` 归一化，
再交给 `build`；`build` 会自己判断能不能铺满整页。


## 为什么"图生视频"优先于"文生视频"


语料里 16/22 段视频提示词都点名了参考帧（"以附件1作为首帧""附件图片是最后完成的效果，作为视频尾帧"）。
原因很实在：纯文生视频的画面不可控，做不出"和 PPT 版面严丝合缝"的容器留白；
先把**构图、留白、色域**用图片钉死，再让模型只负责"动"，成功率高得多。

所以本技能的标准链路是：

```
爬到的真实素材 / 文生图结果  ──当首帧──▶  即梦图生视频  ──▶  mp4  ──▶  整页视频背景
                              ──当尾帧──▶  （定格收束，保证最后一帧能当静帧继续用）
```

## 投放卡怎么用（`promptpack/delivery_card.md`）

`pack` 会为每页生成一张卡，里面已经备好：

- 该页的**留白区坐标**（写成百分比，直接抄进提示词）；
- **要上传的附件图绝对路径**（爬到的素材或文生图结果）；
- 可整段复制的**图片提示词 / 视频提示词 / 负面提示词**；
- 产物**应该放回的精确文件名**。

用户在即梦网页版的操作（点击级）：

1. 打开 `jimeng.jianying.com`，登录（免费额度）。
2. 生图：左侧选「AI 作图 / 图片生成」→ 比例选 **16:9** → 分辨率选最高 →
   把卡里 `image` 段整段粘进提示词框 → 若卡里要求参考图，点「上传参考图」选那个路径的文件 →
   生成 → 下载。
3. 生视频：左侧选「AI 视频 / 视频生成」→ 模式选 **首尾帧**（有两张参考图时）或 **图生视频**（只有一张）→
   比例 **16:9** → 时长选 **5–10 秒**（按卡里写的秒数）→ 粘贴 `video` 段 →
   上传首帧（和尾帧）→ 生成 → 下载。
4. 把下载的文件改名放回卡里写明的路径，例如：
   ```
   gen/p001/image.png
   gen/p001/first.png
   gen/p001/last.png
   gen/p001/video.mp4
   ```
5. 回来跑 `build` + `check`。

**注意**：网页里若模型自作主张画了字，这张**不能用**（会破坏可编辑性）。
重跑时在提示词开头再加一句"画面中绝对不要出现任何文字"，或改用图生视频把文字区锁死。

## 动图（GIF）怎么投放

`asset_kind="gif"` 的页，`scaffold` 会写 `promptpack/pNNN_gif.txt`。两条出片路：

1. **即梦网页版**（首选，元素运动更自然）：登录 → 「图片生成/图片动画」→ 上传该页的参考图
   （`materials/pNNN.jpg` 或该页文生图结果）→ 粘贴 `pNNN_gif.txt` 全文 → 选择"循环/无缝"档位
   → 生成后下载 → 存成 `gen/pNNN/gif.gif`（同目录任意 `*.gif` 也认）。
2. **本机兜底**（无账号也能动，且**保证透明底**）：
   ```
   python scripts/make_gif.py --out gen/p002/anim.gif --kind arc --hue gold --frames 32 --size 800 --secs 3.2
   ```
   四种动效 `arc`（粒子弧线划过，语料 NO.78/80）/ `sweep`（光带横扫）/ `bloom`（水墨晕开，NO.71）/
   `spin`（折扇卷轴旋转，NO.109/142），三种色相 `gold/ink/cyan`；输出带**透明索引**（索引 0 为键色），
   叠在任何背景上都不露框。这条只做"平移/旋转/扩散"这类确定性运动，
   做不出模型级的形变——**能走 1 就走 1**，走了 2 要在报告里写明是本地兜底。

**为什么透明底是硬要求**：实测把纯黑底 GIF 叠在深蓝矢量色场上，渲染图里就是一块明显的方框；
色差却只有 5/255（色场本身很暗），所以不能靠像素差判，`G11` 改用确定性的两条：
**动图不透明 + 这页背景是矢量色场 = 不合格**（叠在暗色实景图上仍允许，语料就是这么用的）。


无论哪条，`build` 都会把动图叠在蒙版**之上**（否则被压暗就白做了），而 `check` 数的是文件真实帧数：
**<10 帧或短边<640 直接判不合格**，单帧 GIF 会被点名"放出来就是静图"。

## 半自动通道（可选）


用户已登录即梦/豆包时，可用 browser-use MCP 代为填提示词与点生成，但：

- 下载与账号操作属于用户侧，**先征得同意**再动；
- 生成结果必须回落到 `gen/` 并过 G11 回收核对，不能只在浏览器里看过就算数。

## 秒数与帧率约定

| 用途 | 时长 | 依据 |
|---|---|---|
| 封面视频 | 5–8 秒 | 语料「尺寸 16 比 9，时长 5 秒」（NO.125） |
| 隔页视频 | 6–10 秒 | 讲者反复说"持续时间和延迟根据视频设置" |
| 循环背景 | 8–10 秒且首尾一致 | NO.173 仓储循环写法 |
| morph 平滑 | 2000ms | 语料 218 次显式时长中的绝对多数 |
| 文字淡入 | delay 6000ms 后 fade 500ms | NO.150 语料 timing 实测 |
| 动图循环 | 3–6 秒、24–51 帧 | 语料 161 个 GIF：最少 24 帧、中位 51 帧 |

## 闸

- **G6**：**量的是成品 slide XML**——视频时长不在 5.0–10.0 秒（含读不出时长）、morph 不在
  1500–2500 毫秒（取 `p14:dur`）、带动效页面 <30%、隔页没有 morph/视频/动图 → 拦。
- **G11**：写了提示词却没有对应 `gen/` 文件 → 列入"待补"，不许当已完成；
  动图页的 GIF 帧数不足同样在这里拦。

- **G7**：成品里若某页其实是整页截图（文字被画进图里）→ 拦。
